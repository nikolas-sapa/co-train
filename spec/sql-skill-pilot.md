## Conditional design: not implemented

Conditional design review complete; implementation, actual capability verification
and owner approval pending. Static review is not runtime verification.
Trusted host controls two separate Linux Docker compartments; no host SQL broker.

PROGRAM: fresh container per program, mounting only selected read-only DB and
allowlisted read-only real runtime bundle. Invoke existing
`run_ptc_program(program, db_path)`/`sql_catalog`, no gold/TaskView.
Minimal project closure: `ptc/{__init__,runtime,sql_arms,sql_runtime,sqlite_safety}.py`,
stdlib/native SQLite; provider harness stays lazy.
Hard memory 1 GiB (`1073741824` bytes), zero swap, 10s external deadline,
cleanup ≤12s, stdout 1 MiB, stderr 64 KiB, program 65,536 UTF-8 bytes,
bounded tmpfs. No whole repository, gold, captures, credentials, Docker socket
or other host filesystem access.

Use local UNIX Docker daemon only and immutable preinstalled local image,
`--pull=never`. Both compartments require nonroot/read-only root, dropped
capabilities/no-new-privileges, private PID/IPC, network none, seccomp denying
sockets/fork/clone, pids=1 and owned cleanup.

SCORER: separate trusted compartment executes unchanged protected EX, including
prediction/gold execution, fetch, normalization and comparison. Never run PROGRAM
Python/state there. Mount only approved scorer code, selected DB and gold.
Gold exists only in controller/scorer. Hard memory 1 GiB,
zero swap, 30s external whole-score deadline, 64 KiB result envelope,
64 KiB stderr, 16 MiB scratch. Return only strict complete existing `ExResult`,
never rows. Host must not fall through to `evidence._score`.
Current host scoring materializes results; 2,000-VM-step progress callbacks and
500,000-row bounds are cooperative, not hard memory/total-byte limits.
Read-only DB access and catching `MemoryError` do not provide resource isolation.
This motivates a new trust boundary, not a demonstrated legacy vulnerability.

OOM/timeout/overflow/malformed responses cause typed grading-resource/infra ABORT,
never fabricated EX=0/invalid-gold outcomes or dropped endpoint cases.
Source abort blocks promotion; endpoint abort remains reported and makes the
experiment INCOMPLETE.

Proposed additive API, not current exports: typed immutable `BoundDockerExecutor`
owns both engines and composite `ExecutionBinding`, no arbitrary callback.
Optional `executor=None` on `start_capture`, `rescore_capture`,
`evaluate_candidate`, `promote_candidate`, `reuse_promoted` preserves trusted-host
v1 defaults. Isolated step launches PROGRAM only; finish launches SCORER only;
rescore may launch SCORER with 0 PROGRAM launches/action replay.
