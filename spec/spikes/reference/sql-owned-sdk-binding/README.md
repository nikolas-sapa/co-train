# Registered SDK binding sensitivity

Mocked-result sensitivity. Separate from the earlier cooperative
`sql-sdk-owned-scope` feasibility reference.

`control.py` runs three fresh qualified `-I -B` interpreters: positive, one-hit
mutant, restored. The original registered SDK, all seven
eligible Tasks and original JSONL writer remain in the path. Each child has a
20-second subprocess timeout; impose an independent 60-second parent watchdog.
Pass an absolute scratch directory with `--output-dir`.
`--case` selects `invalid-to-zero` (default), `score-close-reward`, `env-writer`
or `association`. All four have bounded synthetic qualification below.

Each mutant changes one production AST site in memory. The invalid case converts one
declared mocked `gold_error` result into a valid zero. Acceptance requires one
call-phase failure at `INVALID_NATIVE_STATUS_PUBLISHED_EPISODE`, exactly one
mutation hit, and a fresh restored pass. Source hashes must remain unchanged.
The reward mutant starts/retains close but omits its first pre-reward await,
leaving the finally join intact. The separate writer mutant omits one Env
cleanup await, leaving task-score/reward barriers and the original writer intact.
The association mutant suppresses one actual routing mismatch while retaining
all other checks. Its live cross-context PROGRAM-adapter probe remains fenced
by the original native-allocation denial guard, even in mutant mode.
The matcher requires the actual `AssertionError` message and exact originating
file, function and AST assertion line, not text in a rendered traceback.

## Measured mocked-result qualification

All four cases qualified in twelve fresh children. Each produced positive pytest
exit 0, mutant exit 1 at its exact named assertion with one fault hit, restored
exit 0 with zero hits. Protected source hashes remained unchanged.
The Env mutant reached the original writer prematurely, including its failed
target row; this is independent of the score-close/reward mutant.
The association mutant reached the denied native factory once through the
actual PROGRAM adapter. The positive and restored cases reached it zero times.
Neither positive nor mutant allocated an actual owner.
Python/security reviews approved bounded execution after the original
traceback-matching false-positive risk was corrected.

This is explicitly **mocked-result composition sensitivity**, not a native
decoder/owner/ACK, SQL accuracy or native writer-barrier qualification.
The stronger fast-completed-close/late-sibling-failure race remains unqualified.
Existing integration fixture native, SQL, process and PID guards remain active.
Review source before execution. Pytest output is discarded; receipts contain
only bounded gate/count/status metadata. No provider or real model requests.
